## Wake sources on the earlier installation

The existing Debian kernel exposed `freeze mem` and `[s2idle] deep`. Both suspend counters were zero before and after the checks. PMIC power, PMIC volume-down and GPIO volume-up were registered with their parent wake setting enabled. The active Xfce process qualified for polkit's ordinary and multiple-session suspend actions. A policy check for overriding sleep inhibitors required authentication. NetworkManager and UPower held delay inhibitors. These results describe the awake system and its desktop policy. [Linux system sleep states](https://docs.kernel.org/admin-guide/pm/sleep-states.html)

The live tree disabled `qcom,pmk8350-rtc` at `rtc@6100`, even though the running kernel provided the matching `rtc-pm8xxx` module. A native AArch64 check ran from tmpfs and found that reading `CLOCK_BOOTTIME_ALARM` returned `EINVAL`, and creating a POSIX alarm timer returned `EOPNOTSUPP`. A 100 ms timerfd using the same alarm clock delivered exactly one expiration while the tablet was awake. The kernel's POSIX alarm clock checks for a wake-capable RTC when queried. The timerfd interface can expire on the running CPU without that device. The SSH, LightDM, Bluetooth and NetworkManager services were active at completion. [Clock probe](../tests/suspend/awake-clocks.c) · [Linux alarm timers](https://github.com/torvalds/linux/blob/master/kernel/time/alarmtimer.c) · [Linux timerfd](https://github.com/torvalds/linux/blob/master/fs/timerfd.c)
