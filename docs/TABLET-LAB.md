# Y700 无人值守实机测试

电脑通过 USB NCM 上的 SSH 执行命令和发起重启，核对固定的 SSH 主机密钥。每次试启动通过启动 UUID 和运行内核的 ELF notes 摘要验证身份。两个内核共用版本号，单独比较 `uname -r` 无法区分。测试报告和主机日志保存在此次运行专用目录，平板保留每次受控退出前的内核日志。

## 运行一次测试

平板端的一次性安装使用仓库的 `scripts/install-tablet-lab.sh`，参数为同目录的 `tablet-lab-device.sh` 在平板上的路径。通过已认证的连接传输这两个文件并核对哈希，再以 root 运行安装器。安装器只添加测试助手及三个 systemd 单元。定时器由候选启动参数拉起，普通开机不启用。

在电脑的 WSL 中运行以下命令。USB_SSH 是接收远程命令、支持标准输入并固定主机密钥的 Bash 包装脚本。RUN_ID 和 STATE_DIR 每次新测试使用新值，恢复监控使用同一组值。ENTRY 是已部署并校验的附加启动项文件名去掉 `.conf` 后的部分。两个摘要分别来自候选 Image 和对应 vmlinux 的 ELF `.notes` 段。

```bash
bash scripts/run-tablet-trial.sh "$USB_SSH" "$RUN_ID" "$STATE_DIR" \
    "$ENTRY" "$IMAGE_SHA256" "$NOTES_SHA256" --check "$CHECK_SCRIPT"
```

检查脚本以 root 运行，标准输出、错误和退出状态写入电脑。选择可重复执行的检查，退出码 0 表示检查通过，76 表示检查发现硬件错误并终止本轮，其他错误最多重试一次。每次启动只派发一次。单次检查默认 25 秒，可用 `--check-seconds N` 选择 25 至 3600 秒。对于长检查，在候选内核经 SSH 验明身份后，平板临时将本次启动的软件重启定时器设为检查时长加 45 秒。脚本可以读取 `Y700_TEST_ATTEMPT`。省略 `--check` 可单独验证内核、SSH 和桌面服务；`--exercise-timeout` 会故意不给第一次已观测到的候选启动发送确认。在任何已有 SSH 会话中，可直接执行常规 Debian 命令；主机端的包装脚本也可独立运行，例如 `bash "$USB_SSH" 'uname -r; systemctl is-active ssh lightdm'`。

## 失败、重试和回退

- 引导器的 EFI 变量只读。助手临时将 loader.conf 的匹配范围限制在两个专用入口，启动计数通过 EFI 文件名保存。候选总共可启动两次。原 Debian 的内核、设备树、initrd 和入口保持原有内容。在试启动前保存原 loader.conf；清理前逐字节核对专用文件，遇到外部改动就停止覆盖。[systemd 启动计数](https://systemd.io/AUTOMATIC_BOOT_ASSESSMENT/)
- 电脑掉线、监控程序退出或检查收不到确认时，已启动到 systemd 的平板会在开机约 100 秒时自行请求重启。候选参数包含 `panic=15 oops=panic`，使能够进入 panic 处理程序的故障具备延时重启路径。实机只核对这两个设置生效，没有主动制造内核崩溃。
- 电脑重连后核对新启动 UUID、内核、SSH 和 LightDM。若检测到 GPU 超时、错误的内核或测试次数耗尽，就结束本轮并恢复默认规则。电脑默认等待首个候选启动 420 秒；遇到已知的关机或启动菜单延迟，可用 `--startup-seconds N` 独立设置 60 至 3600 秒。候选系统的 100 秒无人接管定时器从设备启动时开始。电脑发现首个候选后重新计算 420 秒预算，派发长检查时才追加负载时间。过期时已连上的候选会被要求回退。通过条件包括检查成功、原系统重新上线和临时启动规则已清理。
- 电脑监控重启后可用同一命令恢复。设备端状态在 `/var/lib/y700-lab/runs/RUN_ID/`，主机端查看 `state.json`、`events.log`、`device-events.log` 以及各次 `check-*.log`。若准备阶段中断且仍在基线，可用助手的 `status` 核对活动 ID 和启动 UUID，再以 `close RUN_ID BOOT_UUID` 撤销本轮。
- 软件定时器需要内核和 PID 1 能运行。该机当前没有向 Linux 注册的硬件看门狗。若在启动初期卡死、整个内核停止响应或设备彻底关机，主机只能记录失联。启动计数控制下一次上电的选择，不能给停住的平板产生复位信号。

## 复核

2026-11-18 在国行 Y700 上完成三轮，共观察到九次实际重启。第一次故意不确认，平板超时后自行重启。第二轮命令第一次返回 75，重启后第二次返回 0。第三轮命令两次都返回 75，控制端记为失败并停止重试。三轮均核对了两个独立的候选启动 UUID 和随后恢复的基线，默认启动规则最终与试前逐字节一致。电脑端日志记录顺序作为跨重启时间依据，平板时间在校时前可能回退。[实机验收记录](research/unattended-tablet-trials.json)

`tests/tablet-boot-count.py` 使用与平板相同的 systemd-boot、QEMU 版 U-Boot 和跨三次启动保留写入的 FAT 磁盘，从串口读取真正启动的内核参数，并检查每一次 EFI 文件重命名。首次虚拟启动因无根分区触发内核 panic，3 秒后自动复位；下一次启动仍按计数进行。参数依次为板级构建树、QEMU 工具目录、新建的测试输出目录。故障命令演练脚本为 `tests/tablet-command-retry.sh`。
