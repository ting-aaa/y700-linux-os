# dev12.10 镜像验证

2026-11-21，国行 TB320FC_PRC（16 GiB / 512 GB）通过 USB 在内存中运行了 dev12.10 根文件系统。测试使用平板当前的板级内核。新版 Parole 和专用 Iris 插件均直接来自只读根镜像。测试程序核对了两份二进制、系统自带的 Debian 插件和全部 1,240 项已安装软件包。[镜像与解包](DEV12.10-IMAGE.md)

## 发行文件

| 文件 | 字节数 | SHA-256 |
| --- | ---: | --- |
| 完整开发镜像 TAR | 1,395,589,120 | `ded90f1450d3d43642a3c8a7fe3077af7d6e59d9f9bb2b3485207edcfe0077eb` |
| TAR 解出的 root.ext4 | 6,442,450,944 | `18e75eff99d13c9aa6e446eaf03d79d5ac0122f9815f9419d96715a2e6e426fd` |
| 内存试用包的 initrd | 1,358,582,372 | `4c5aa99c89167f8e4cd7face573cdeba75e4a97a682e4e8f718a8ea665330cf3` |
| 从通用 dev12.9 重建本批次 ext4 的 QCOW2 差分 | 20,250,624 | `b1ef612a515b7c99edba6516c1f12e51c654177fc14d21e5394246e22a22ea01` |

TAR 中的安装包清单与你从运行中的 Debian 按包名、版本、架构排序得到的 1,240 项一致，SHA-256 为 `ffb8818f1fd41efb3b7c7a14782abd62b37bf5dd687cfaa923d3419d785f51c3`。内存试用包中的 SquashFS 解压后得到上表中的同一份 ext4。将 dev12.9 根镜像传给 dev12.10 内存构建器会在输出目录创建前因 SHA-256 不符而中止。

在 Linux 上，普通用户按照差分包附带的说明，从 dev12.9 的原始 `root.ext4` 重建了此版本。完整 ext4 的 SHA-256 一致，`e2fsck -fn` 检查通过。另行从源执行安装配方时，APT 缓存和 dpkg 时间日志会改变完整镜像摘要。已对旧版升级包实测，安装和回退请求遇到 dev12.10 的版本收据都会在写入前退出。在 dev12.9 上仍能完成安装和回退。

## 在平板上播放视频

在 2560×1600、200% 缩放的隔离桌面中，普通用户从 Thunar 打开三段分辨率为 1080p 的测试视频，播放器为 `4.18.2-1+y7002`。每种格式都进行了三轮向前、向后跳转，随后暂停和恢复。自动化程序核对了跳转后的画面、硬件输出缓冲区以及每次拖动实际产生的跳转请求数。18 次拖动均只产生一次请求。

| 格式 | 平板使用的硬件解码器 | 日志中的输出缓冲区数 |
| --- | --- | ---: |
| H.264 / MP4 | `v4l2h264dec` | 109 |
| H.265 / MP4 | `v4l2h265dec` | 110 |
| VP9 / WebM | `v4l2vp9dec` | 107 |

播放按钮的点击区域为 96×96 设备像素，进度条的可点击高度为 96 设备像素，均相当于 48 个逻辑像素。此轮输入使用自动化指针，实际手指操作仍待体验。播放器退出后 Iris 回到运行时挂起状态。测试前后的原系统启动、桌面会话、服务、挂载、交换空间及传感器 DSP 状态一致，临时挂载与回环设备已释放。[实机测试入口](../tests/video-codec/run-parole-tablet.sh)

```bash
bash tests/video-codec/run-parole-tablet.sh --transport "$usb_ssh" "$ram_bundle" \
    --preinstalled "$indexed_clips" "$device_xvfb_usr"
bash tests/ram-userspace/run.sh "$usb_ssh" "$ram_bundle" "$device_xvfb_usr"
```

## 在平板上使用触屏桌面

另一次测试在 36 秒内通过 USB 传入同一份 initrd。普通用户进入 200% 缩放的 Xfce 隔离桌面，用 Onboard 在 Thunar 输入 `hello` 并创建文件夹。文件夹只出现在 RAM 写层。亮度设置窗口完成了「关 → 开 → 关」切换，并提示测试环境缺少光线传感器。实体背光和光线传感器未引入这个测试桌面，结束时原会话和挂载检查通过。

## ARM64 无盘启动

电脑上的 9 GiB ARM64 虚拟机从发行包的内核和 initrd 启动。系统在零磁盘和零活动交换空间下进入 systemd，核对了锁定的初始账户、软件包和播放器收据。通过虚拟触屏设密后，LightDM 登录进入普通账户的 Xfce，测试文件只存在于 tmpfs 写层。系统随后正常关机，试用包四个文件的校验值与启动前一致。[无盘启动复测入口](../tests/ram-trial/README.md)

## 从完整 TAR 启动

另一台 ARM64 虚拟机通过虚拟 U-Boot 和 EFI 从 TAR 实际解出的启动分区、内核和根文件系统启动。虚拟触屏首次输入两次不同的密码时账户保持锁定，输入相同密码后完成设密，再通过 LightDM 登录 Xfce。普通用户的 MP4 和 WebM 均关联到镜像自带的 Parole。播放 H.264 时核对了正在运行的程序和三组画面变化，虚拟机使用 libav 软件解码。平板使用物理解码器的结果列在上表。整包在实体平板上的冷启动仍待验证。[EFI 复测入口](../tests/combined-efi/README.md)
