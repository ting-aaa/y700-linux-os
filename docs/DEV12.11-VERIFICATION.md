# dev12.11 发行镜像和实机验证

2026-11-21，国行 Y700 二代（TB320FC_PRC，16 GiB / 512 GB）从内置 UFS 启动了独立安装的 Debian dev12.11。第二次限次启动确认了新根、图形登录界面、USB SSH、Wi-Fi 链路和原账户身份。普通用户通过 FD730 和 Turnip 完成了短时离屏渲染与像素回读。[镜像解包说明](DEV12.11-IMAGE.md)

## 电脑上的 ARM64 验证

完整发行文件经虚拟 U-Boot、systemd-boot、发行内核和 initrd 启动。运行中的 Debian 核对了 1,240 个软件包的名称、版本、架构，以及内核 notes 和相机版本收据。两次桌面启动都通过触屏首次注册和 PAM 登录 Xfce。第二次从正式桌面入口打开相机，在 1024 × 768 虚拟显示器上按 200% Qt 缩放测得窗口宽 492 像素、取消按钮高 96 像素，Type-B 触碰成功关闭窗口。Parole 随后以软件解码显示了 H.264 的三组预期色块。第一次运行中播放器已启动，但画面采样未捕获色块，原因未定位。第二次正常关机后复核了源镜像哈希。虚拟机使用自己的设备树；桌面本身在该分辨率下采用 100% 缩放。[EFI 桌面验收](../tests/combined-efi/README.md)

另一项测试在虚拟 GPT 上重建内置安装的两层文件系统，用生产内核和文件根 initrd 直接启动。新系统以读写方式挂载独立 32 GiB 根和 1 GiB EFI，进入 systemd。关机后读回了两个持久化标记，旧版两个镜像的哈希一致，两层 ext4 和 FAT 的只读检查均通过。另一次故意换入错误的 FAT，initrd 在开放持久根写入之前终止。外层 EFI 的独立固件测试验证了限次项消耗一次、下一次启动选择 dev12.10。[嵌套根启动与回退测试](../tests/installed-trial/README.md)

## 机主数据和两次实机试启动

原 dev12.10 的 32 GiB 根和 1 GiB EFI 均保留。安装程序为 dev12.11 创建了独立文件，新根 UUID 为 `c0e447e4-82db-59ee-91d6-0e1ec9d5f45e`，内层 EFI 为 `31EC-3084`。迁移校验覆盖机主主目录、账户与组、已存无线配置、蓝牙和 USB SSH 身份。原外层 EFI 的 29 个文件逐项校验通过；新增内核、设备树、initrd 和启动项后共 33 个文件。两份文件系统使用同一台平板既有的 U-Boot。[迁移实现](../scripts/personalize-file-install.sh) · [限次控制器](../scripts/arm-installed-trial.sh)

- 第一次试启动后，主机重新连入 dev12.10。只读挂载 dev12.11 根时发现新增了 Xorg、LightDM 和登录界面日志，说明新系统已进入图形登录阶段。此次未在期限内取得新系统的维护连接，未能直接记录触发回退的事件。
- 第二次试启动通过 USB SSH 读回 dev12.11 的新根 UUID，确认本次启动并停止四分钟回退定时器。平板位于 LightDM 登录界面，用户口令已配置，机主目录、机器、蓝牙和 SSH 公钥身份通过校验。Wi-Fi 链路已连接，蓝牙控制器已上电，系统枚举出触摸设备、DSI、背光、两个扬声器功放及三个相机子设备。这次检查停留在登录界面。[实机桌面检查](../scripts/check-installed-desktop.sh)

## 实机 GPU 与清醒状态闹钟

同一次限次启动中，普通用户两次运行 FD730 EGL/GLES 离屏测试。两次均在三个上下文提交 12 帧并核对 24,576 个像素，首次检查未出现新的内核 GPU 故障记录。Turnip 识别为 Adreno 730，完成四次 Vulkan 渲染和四次传输，回读并核对 8,192 个像素（32,768 字节）。测量期间 GPU 的运行时挂起时间累计增加 694 毫秒；这组负载持续数秒。浏览器加速与长时间 GPU 稳定性需要各自的工作负载验证。[GPU 测试实现](../tests/gpu-resume/)

同一系统识别 `rtc-pm8xxx` 驱动的 `rtc1`，`hctosys=0`。平板保持清醒时设置四秒闹钟，约 4.09 秒收到一次 RTC 中断，测试结束后恢复了原先已关闭的闹钟状态。[RTC 测试](../tests/rtc-alias/)

电脑上的原始记录分布在 `out/dev12.11-efi-verified/`、`out/dev12.11-nested-verified/` 和 `out/dev12.11-installed-boot/`。实机第二轮桌面检查 `desktop-trial.log` 的 SHA-256 为 `56e6d62913180cfbb5b6407c53f326e3d6b4896c433df046851eb1186c5c3750`，GPU 与 RTC 记录 `trial-render-rtc.log` 的 SHA-256 为 `f8868ffb80995d466af2382e064613cb7ff8e21b5bd95ded77b21f73a68fdec7`。
## 默认启动和整机待机

确认第二次试启动后，将 `y700-file-12-11.conf` 设为默认项并正常重启。固件读回的选择项与默认项一致，正在使用新版 32 GiB 根和 1 GiB 内层 EFI，原账户已配置，LightDM 在内屏显示登录界面。旧 dev12.10 和原 Debian 入口均保留。外层 EFI 共 33 个文件，原文件已按安装前的清单核对，选择器和启动时更新的随机种子单独检查。主机上的发行镜像保留，平板上已释放 7 GiB 临时传输空间。

在这次正式启动中，通过 logind 让整机两次进入 `s2idle`。RTC 预约相对于 PMK8350 自身计时。内核追踪的唤醒 IRQ 两次均为 247，对应 `pm8xxx_rtc_alarm`。成功次数由 0 增至 2，失败次数保持 0，两次的启动 ID 相同。根据 Linux 两种时钟的差值，实际挂起约 19.01 秒和 89.17 秒。第二轮的 90 秒闹钟作为电源键测试的后备，此轮电源键 IRQ 计数未变。两次测试结束后重新读取了原有闹钟，均已恢复。RTC 测量进程在唤醒早期读取计数器，最终计数及唤醒来源由系统恢复后的独立控制程序核对。这两轮在 USB 连接、图形登录界面下进行。下节记录了之后的深度休眠试验。[实机挂起控制程序](../tests/suspend/board-cycle.sh)

唤醒后，内屏仍启用 1600 × 2560 模式，USB SSH 可用，Wi-Fi 的 IPv4、IPv6 网关各应答三次。第二次唤醒后连续 20 轮离屏图形校验通过，每轮从 GPU 运行时挂起状态开始。每轮用 GLES 校验 24,576 个像素，用 Vulkan 校验 8,192 个像素。Iris 也在醒后通过 H.264 1920 × 1080 实测，硬解的 24 帧与软件参考逐像素一致，解码器随后再次进入运行时挂起。[视频解码核验](VIDEO-CODEC-BOARD.md)
随后在同一次正式启动上运行 306 秒混合图形循环。360 轮均从 Adreno 运行时挂起状态开始；每轮先用 FD730 在三个 GLES 上下文绘制并验证 12 帧，再用 Turnip 完成四次渲染及传输。360 轮 GLES 和 360 轮 Vulkan 的数据全部吻合，日志中未检出所检查的 GPU、GMU 或显示超时与故障。每轮之间有短暂停顿，持续满负荷、长时间游戏和浏览器有各自的验收范围。电脑上 `out/dev12.11-verified/mixed-five-minutes.log` 保存汇总，同目录的 `mixed-five-minutes-detail.log` 保存每次渲染的 GPU 计数与回读结果。

## 实机深度休眠

在相同的正式启动中，平板以 100% 电量连接 USB，停留在 LightDM 登录界面。为这一次试验临时选择 `deep`，让 PMK8350 预约 20 秒后唤醒。内核依次记录 `machine_suspend[3] begin`、`psci_system_suspend_enter` 和 `machine_suspend[3] end`。系统成功次数从 2 增至 3，失败次数保持 0。根据 BOOTTIME 与 MONOTONIC 的增量之差，实际睡眠 17.956 秒。唤醒追踪只有 IRQ 247，RTC 收到一个闹钟中断。测试后独立读回原闹钟，系统模式恢复为 `[s2idle] deep`。这一次测量不含拔线后的电流和电池消耗。[内核路径与测量方法](SUSPEND-ROUTING.md)

深睡后，通过 USB 连回同一启动。Wi-Fi 的 IPv4 和 IPv6 网关各应答三次，内屏仍启用 1600 × 2560 模式。普通账户完成 12 轮 GLES 与 Vulkan 对照，每轮核对 24,576 个 GLES 像素和 8,192 个 Vulkan 像素。加速度、陀螺仪、磁场、环境光、接近、罗盘和霍尔服务全部返回有效样本。蓝牙控制器已上电，键鼠输入留待实体外设验证。

Chromium 的 Adreno 窗口测试在深睡后另完成 1,800 帧，耗时 29.996 秒，内屏窗口的四个颜色正确。播放器的 Iris 硬件解码器输出 24 帧 1920 × 1080 H.264，各帧与软件参考逐像素一致。解码器再次回到运行时挂起，软件包与服务复核通过。本轮原始记录和校验清单保存在 `out/dev12.11-deep-wake/`。[醒后解码测试](VIDEO-CODEC-BOARD.md)

## Chromium WebGL 2

在同一台平板的 dev12.11 上，以桌面账户启动发行版内的 Chromium 156，使用全新的临时配置和本地测试页。默认浏览器入口带有 `--disable-gpu`，返回 SwiftShader。单独选择 ANGLE/Vulkan 和 Turnip 后，WebGL 2 报告 Adreno 730，60 帧的像素采样全部正确，浏览器 GPU 子进程出现已完成的 MSM 工作计数。测量期间渲染进程沙箱生效。此轮使用无窗口模式；日常启动器仍默认使用软件渲染。两轮之后系统失败单元和本轮检查的内核图形错误计数均为零。[测试说明](../tests/chromium-gpu.md)

随后在平板上将单个 `y700-platform` 软件包升级至 `0.1.0~dev12.8+gpu1`，在 Xfce「设置管理器 → 硬件 → Chromium 图形」加入按账户选择加速的开关。已安装的 1,240 个软件包清单和四个新增或更新的功能文件均通过复核。这个更新随附原包和回退脚本，封存的 dev12.11 完整镜像仍使用原包。[软件包与操作说明](CHROMIUM-GRAPHICS.md)

在同一次启动上，用两个临时配置分别测试发行版的 `/usr/bin/chromium`。默认设置下 SwiftShader 通过 60 帧，浏览器未产生可归属的 MSM GPU 工作。开启设置后，浏览器报告 Turnip Adreno 730，60 帧每帧四个像素全部正确，GPU 进程的 MSM 计数显示已完成硬件工作。两轮均观测到渲染进程 seccomp 生效，且未发现所检查的沙箱绕过参数。两次均为无窗口测试。机主账户保留原有偏好。

随后以普通临时账户运行有窗口的正式 Chromium。实机仅启用内屏 DSI，浏览器在 640 × 480 的隔离 X11 窗口中绘制。开启同一个图形设置后，Turnip 先通过 60 帧，再两次各通过 1,800 帧，后两次分别耗时 29.977 和 29.969 秒。每一帧校验四个着色器采样点。两次长测中，主 Xorg 也连续三次从无遮挡的测试窗口读回黑、红、绿、蓝四个预期颜色，当时内屏和背光均已开启。浏览器 GPU 子进程记录了 MSM 已完成工作，渲染进程沙箱生效。关闭设置时，同一窗口无法创建 WebGL 2 上下文，独立 Canvas 2D 对照在 980 毫秒内完成 60 帧和相同的窗口采样。每次退出均恢复了原先的熄屏状态。[窗口测试实现](../tests/chromium-window/)

真实 Xorg 提供 DRI3 和 Present，测试使用的 Xephyr 嵌套显示器缺少 DRI3。这组结果验证了 Chromium 的硬件 WebGL 绘制和窗口像素传递，原生 Chromium Vulkan 交换链、长时间交互式浏览及浏览器的视频硬解仍需分别测量。实机运行记录在 `out/dev12.11-desktop-update/`，其中 `RECEIPTS.sha256` 校验各轮原始日志，`PACKAGES.sha256` 校验更新与回退文件。
