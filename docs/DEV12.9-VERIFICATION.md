# dev12.9 镜像与实机验证

2026-11-21 在一台国行 TB320FC_PRC（16 GiB 内存、512 GB 内置存储）和电脑上的 ARM64 虚拟机验证了同一份 Debian 13 根文件系统。完整镜像放在 `out/dev12.9-board/`，内存试用包放在 `out/dev12.9-ram-trial/`。平板可以通过 USB 接收试用包，在现有内核上运行新版应用，结束后释放 RAM。整个流程无需备用卡。[完整镜像和构建方法](DEV12.9-IMAGE.md)

普通 Linux 账户从 Windows 交付目录读取并解包了 TAR。解出的 U-Boot、EFI 分区和根文件系统逐项匹配封存源的 SHA-256，FAT 和 ext4 均通过只读检查。从解出镜像的 dpkg 数据库独立导出的 1,240 项记录与随包清单逐字节相同。用上一版 dev12.8 根镜像尝试打包 dev12.9 时，打包器因缺少媒体文件校验记录而中止。

## 平板上的预装播放器

USB 把试用包传到平板的 tmpfs。平板核对了整个 initrd、只读 SquashFS、6 GiB ext4 和 1,240 项已安装软件包。普通用户在 2560×1600、200% 缩放的私有 X11 桌面里通过 Thunar 打开三个 1080p 合成视频。Parole 的启动器和插件都来自这个镜像。测试通过 X11 取样确认了三种预期的画面变化。

| 实际打开的文件 | 平板硬件解码器 | 日志中观察到的输出缓冲区数 |
| --- | --- | ---: |
| H.264 MP4 | `v4l2h264dec` | 10 |
| H.265 MP4 | `v4l2h265dec` | 10 |
| VP9 WebM | `v4l2vp9dec` | 10 |

VP9 启动关键帧也得到确认。播放结束后，Iris 回到运行时挂起状态。测试前后的系统启动标识、实体桌面会话、桌面和网络服务、挂载、交换空间和传感器 DSP 状态一致，临时挂载与回环设备全部释放。上表记录了打开文件时的输出。此前另有三段各 48 帧的逐帧一致性测试。[解码器验证](VIDEO-CODEC-BOARD.md)

另一次独立的桌面试用通过 USB 在 34 秒内传输了 1,357,505,124 字节。普通用户在 200% 缩放的 Xfce 桌面打开亮度设置，开关依次经过关、开、关。测试向该桌面隐藏了实体背光和光线传感器，并确认设置界面能解释传感器缺失状态。Onboard 屏幕键盘在 Thunar 中输入了文件夹名 `hello`，新文件夹只存在于 RAM 临时层。

实机复测入口接受已固定主机身份的 USB SSH 脚本、含三个合成视频的目录，以及设备上现成的测试显示工具目录。

```bash
bash tests/video-codec/run-parole-tablet.sh "$usb_ssh" out/dev12.9-ram-trial \
    --preinstalled "$synthetic_1080p_clips" "$device_xvfb_usr"
bash tests/ram-userspace/run.sh "$usb_ssh" out/dev12.9-ram-trial "$device_xvfb_usr"
```

## 电脑上的系统启动

ARM64 虚拟机通过虚拟 U-Boot、镜像自带的 EFI 加载器和内核启动完整系统。测试使用虚拟触屏完成首次设密和 LightDM 登录，进入普通用户的 Xfce。屏幕键盘、音量面板、电源和亮度组件均已运行。双击文件所用的 MP4 与 WebM 文件关联都指向 Parole。在没有视频解码设备的虚拟机里，普通账户通过该入口播放 H.264，观察到三种颜色组合和软件解码插件。这一项测试使用 1024×768、100% 缩放。[EFI 验证入口](../tests/combined-efi/README.md)

另一台配置 9 GiB RAM 的 ARM64 虚拟机直接启动内存试用包，并在没有任何磁盘和活动交换空间的条件下进入 Xfce。临时账户通过虚拟触屏设密，LightDM 登录后启动了普通用户的亮度服务，默认关闭自动亮度。测试文件只出现在 tmpfs 写层，随后系统正常关机。测试前后内存包的四个文件校验值一致。[无盘启动测试](../tests/ram-trial/README.md)

新版在平板上的独立内核启动、内置屏幕上的首次设密、浏览器硬解和长时间播放功耗仍待实测。蓝牙实体键鼠等外设的验收状态单独记录。[整机功能状态](STATUS.md)
