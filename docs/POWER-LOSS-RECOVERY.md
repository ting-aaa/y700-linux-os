# dev12.10 异常关机后的启动恢复

内置安装把可写的 Debian 根文件系统和 EFI 文件系统放在原 Debian 分区的两个文件里。意外掉电时，外层 ext4 和内层 ext4 可能同时留下待回放的日志。原 dev12.10 启动项在看到这一状态时退出。新增启动项 **Y700 dev12.10 (filesystem recovery)** 使用同一套内核、系统和个人文件，能够按顺序恢复这两层。

## 启动时怎样处理

1. 通过板型、UFS 路径、分区标签、UUID 和 ext4 状态定位存储。用 `ro,noload` 和只读 loop 核对原系统、镜像目录权限、新根容量和 dev12.10 版本收据。初检避免触发日志写入。
2. 如有待处理事务，先让内核回放外层日志并清理孤立 inode。卸载并检查状态后，重新解析、核对里面的文件。接下来对需要恢复的内层 ext4 执行相同的操作，重新检查版本收据。标记有文件系统错误的卷需要离线处理。[Linux ext4 挂载和日志语义](https://docs.kernel.org/admin-guide/ext4.html#options)
3. 对 FAT 单独检查。典型的异常关机留下一个未正常卸载标志，空闲簇计数也可能落后。启动程序在有空间时复制 1 GiB 的 FAT 到限额 tmpfs，在副本运行随发行根校验的 ARM64 `fsck.fat`。只有只读复查通过、并逐字节证明修正仅涉及该标志及主 FSInfo 的空闲数时，才将修正写回。先同步计数，再同步标志。当内存不足或检查发现其他修改需求时，可以只读挂载的 EFI 会以只读方式提供给系统；此时 `/run/initramfs/boot-fat-status` 记录 `readonly`。几何信息不符时停止启动。[FAT 检查实现](../src/boot/file-recovery-fat)

恢复针对仍能读取、身份可核对的存储。已同步文件的回读测试见下表。应用尚未保存的数据、UFS 硬件故障和严重的文件系统损坏需要另行处理。发生启动前检查失败时，限次试启动请求重启至回退项，普通恢复入口则提示下次选择旧 Debian 后关机。内核自身在启动后崩溃时仍按内核的 panic 配置处理。

## 验证

ARM64 QEMU 使用发行内核和真实板级 initramfs。客机在挂载的根与 FAT 上写入随机标记并同步文件及父目录，宿主随即终止指定虚拟机进程。测试分别把同一份断电磁盘的副本交给原入口和恢复入口。虚拟存储的逻辑扇区为 4096 字节。

| 检查 | 结果 |
| --- | --- |
| 原启动项 | 在外层 ext4 检查处拒绝启动。 |
| 6 GiB 根 | 外层、内层按序恢复，进入 systemd，两份标记内容匹配，内层 EFI 重新可写。正常关机后两次 `e2fsck -fn` 和一次 `fsck.fat -n` 均返回 0。 |
| 32 GiB 安装容量 | 在另一份实际扩为 8,388,608 个 4 KiB 块的根镜像上重复断电测试。两层 ext4 及 FAT 恢复，镜像可写，关机后的三项离线文件系统检查通过。 |
| 身份不符 | 换入错误的版本收据后，恢复入口停止。磁盘内容与该次测试前相同。 |
| FAT 扩大修改范围 | 出现丢失簇、备份引导扇区不一致或未知状态时，专用检查用例验证原始字节保留。 |

## 国行平板上的默认入口

同一台 16 GiB / 512 GB 国行平板采用独立的恢复入口，并继续使用已安装的 32 GiB 根。添加时复核了原 EFI 上全部 25 个文件。首次正常重启由固件消费一次试启动机会，USB 重连后确认根及内层 EFI 均可写、图形登录及 Wi-Fi 已恢复，随后停止回退定时器，设为默认。第二次正常重启读回固件选择 `y700-recovery-12-10.conf`，两份保存的无线配置保留，IPv4 与 IPv6 各三次网关探测全部成功。最终复核原有的 23 个静态 EFI 文件、四个新增文件及临时启动项清理情况。此次真机验证使用正常重启，强制断电仅在虚拟机执行。[实机回退办法](DEV12.10-INSTALLATION.md)

## 从发行文件构建

在 Linux 电脑上用通用 dev12.10 发行档解出的 `images` 目录运行以下命令。工具校验原始 6 GiB 根镜像后提取 Debian 用户空间工具，已扩至 32 GiB 的个人系统可以使用同一启动入口。

```sh
bash scripts/build-file-trial-entry.sh --dev12.10-recovery images recovery-entry
(cd recovery-entry && sha256sum --strict -c SHA256SUMS)
```

入口的内核与设备树沿用 dev12.10。补充 initramfs 和菜单使用独立路径。维护工具支持在原 Debian 或 dev12.10 为默认项时，将四个文件加入已确认的物理 EFI 分区。在已安装的文件根系统中，`/boot` 是内层 EFI，固件读取的是外层 EFI。[原安装及数据位置](DEV12.10-INSTALLATION.md)
