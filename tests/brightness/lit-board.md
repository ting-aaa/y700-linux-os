# Verify the internal backlight controller

On the permanent dev12.11 kernel, run `bash lit-board.sh` as root for a read-only snapshot. Add `--expect-lit 102` or `--expect-blank 102` to check that the saved request is 102 in the specified state. The lit check requires a connected, enabled DSI-1 with DPMS On, backlight power 0, LED enable set and the actual 11-bit programmed level. The blank check requires backlight power 4, LED enable clear and the programmed level zero. Both check all four current-sink channel selections.

For one reversible adjustment, place both scripts together under a root-owned private directory in `/run` and run `bash lit-board-step.sh --step` with the panel already lit at 102. It submits 122 and then 102 through logind as the foreground X11 session's UID. It reads the chip after each request, with an independent 25-second conditional restore for shell interruption. Allow that timer to finish before removing the scripts after an incomplete run. A change of foreground session, another requested level or denial by the existing seat policy stops the test. The greeter exercises the LightDM account. A logged-in owner session exercises its own account. Display blanking and login are controlled separately.

The CN350 runtime device tree places KTZ8866 at address 0x11 below I²C controller 0x988000. The Linux board driver registers the chip as the backlight of the NT36523N panel. It programs the three low bits of register 0x04 before the eight high bits of 0x05 and uses bit 6 of 0x08 to enable the LEDs. Bits 0–5 of 0x08 select the current sinks. The Linux sysfs `actual_brightness` attribute falls back to the requested level on this driver. [KTZ8866 datasheet, tables 9–11](https://www.kinet-ic.com/uploads/web/KTZ8866/KTZ8866-04b.pdf#page=28) · [Y700 driver](https://github.com/dianqk/nixos-android-devices/blob/8dcb481fc2ce91794fd294630e06f15a52ec7513/pkgs/linux-kernel/sm8475/asphalt/patches/local/0002-asphalt-display.patch)

The driver uses an uncached 8-bit regmap. The observer checks the bound client, OF node, driver, regmap range and cache metadata before reading two exact ranges from `debugfs` through the kernel driver. A complete register dump can clear latched faults at 0x0f. The dev12.11 ARM64 Perl syscall trace on a synthetic register file confirmed a 14-byte read at offset 28 and a 7-byte read at offset 56. Each snapshot samples twice and requires matching reads and display state. These values establish controller programming and enable state. LED current and panel luminance require separate instruments.
