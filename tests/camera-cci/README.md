# Asphalt main camera CCI combined read

The pinned Linux 7.3.4 CCI driver sends a register prefix as a queue 0 `WRITE` with STOP, waits, and submits the read separately on queue 1. The CN350 `camera.ko` and Qualcomm's public SM8450 camera driver use queue 1 with `SET_PARAM`, `LOCK`, `WRITE_DISABLE_P`, `READ`, `UNLOCK` in one start. The shipped module places `WRITE_DISABLE_P` (`0x0b`) at `.text+0x129a10` and `READ` (`0x0a`) at `0x129a5c`. The November 9 Qualcomm Linux series updates revision detection, FIFO, and single-direction transfer limits. Its published command path still does not combine a prefix write with the read. [CN350 binary provenance](../../docs/CAMERA-FOCUS-PROBE.md#controller-clock-and-transfer-shape) · [Qualcomm SM8450 queue sequence](https://github.com/OnePlusOSS/android_kernel_modules_and_devicetree_oneplus_sm8450/blob/877203a7cf9b79973d44a9db716490f95d820110/vendor/qcom/opensource/camera-kernel/drivers/cam_sensor_module/cam_cci/cam_cci_core.c#L1311-L1433) · [Linux CCI patch series](https://lore-kernel.gnuweeb.org/linux-i2c/20261109-cci-imp-v4-0-4dc4095dd052%40oss.qualcomm.com/T/) · [Linux combined transaction contract](https://docs.kernel.org/i2c/i2c-protocol.html#combined-transactions)

The isolated [candidate patch](combined-read.patch) uses the stock five-word command sequence on `lenovo,asphalt`'s `qcom,sm8450-cci` instance at `0xac15000`, master 0. It selects two messages to the same 7-bit address, with a one- or two-byte prefix followed by a fixed read of 1–12 bytes. `I2C_M_DMA_SAFE` may decorate either buffer. The five words fit the baseline 16-word queue 1. The driver still discards the first FIFO byte and expects `floor(n / 4) + 1` words. It waits for the queue word count to reach zero after `RD_DONE`, with the existing reset recovery if the wait times out. Other transfer shapes, standalone messages, CCI0 master 1 and CCI1 (including the WL2864C) continue through the pinned path. The candidate leaves the clock rates, timing tables, rail sequencing and device trees unchanged. [Baseline driver](https://github.com/torvalds/linux/blob/f24ba334afafc70c3149e9db9c0cf8ecc6d52a09/drivers/i2c/busses/i2c-qcom-cci.c#L291-L451)

Keep this candidate confined to the PC fixture. On the physical tablet, the idle and powered GT9768 reads and the powered EEPROM read all returned `-ENXIO` on queue 0 at both the 19.2 and 37.5 MHz controller rates. Queue 1 was never submitted. The prefix queue's status does not distinguish an address NACK from a data-byte NACK. With the original 19.2 MHz clock and original split queues, holding WL2864C LDO5 at 2.8 V during the stock main-sensor power sequence subsequently returned GT9768 ID `0xe9` and an EEPROM AF block with valid CRC and ordered endpoints. This establishes an operating configuration for both requests. [Physical trials](../../docs/CAMERA-FOCUS-PROBE.md)

The patch would also alter matching reads on the already working HI1339 at `0x20`. Its guard checks master and transfer shape, without requiring one of the two accessory addresses or an unbound client. The added trailing-UNLOCK timeout calls `cci_reset()`, which resets the entire controller, including the front sensor's master. The Linux adapter lock held during a transfer covers only that adapter. The single-master fake MMIO test does not establish concurrent transfer safety or physical repeated-START timing.

## PC verification

Run in Linux with the configured pinned ARM64 tree and a new evidence directory. The fixture requires the compiler used for the original Kbuild command, a host C compiler, AArch64 GCC, `qemu-aarch64`, `uv`, and binutils.

```sh
bash tests/camera-cci/run.sh "$LINUX_734" "$NEW_EVIDENCE_DIR"
```

The script verifies the baseline CCI source hash, patches an isolated copy, and compiles the exact interrupt handler, transfer functions and FIFO decoder into a fake-MMIO test on the host and under AArch64 user-mode QEMU. The tests assert the expected queue words for GT9768's byte register, the EEPROM's two-byte pointer and eleven-byte read, and the twelve-byte limit. They also exercise delayed unlock, NACK and reset recovery, invalid FIFO level, PM failure, legacy clock-independent queue paths, and prefix-versus-read failures in the split path. The separate ARM64 kernel driver object compiles using the pinned tree's Kbuild flags. The fake MMIO model cannot verify actual SCL/SDA transitions or timing. The patch has not been booted or used on the tablet.
